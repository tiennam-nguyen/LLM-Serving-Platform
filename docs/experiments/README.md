# Experiment Methodology & Reproducibility Guide

This guide establishes the reproducibility standards and experiment lifecycle for the **Adaptive LLM Serving Platform**.

---

## 1. Experiment Lifecycle & Traceability

Every published benchmark result or comparative report must follow an unbroken line of experimental evidence:

```text
[Experiment Manifest]
        │ (Defines: commit hash, hardware, model, policy, seed, workload)
        ▼
   [Raw Execution Data]
        │ (Unmodified JSONL / CSV timing logs: TTFT, ITL, request latency)
        ▼
   [Processed Summaries]
        │ (Aggregated percentiles: P50, P90, P99, tokens/sec, error rates)
        ▼
   [Generated Figures]
        │ (Reproducible visualization charts)
        ▼
   [Final Report / Paper]
```

---

## 2. Directory Conventions

- `experiments/manifests/`: Configuration files detailing the exact parameters of each run.
- `experiments/raw/`: Raw timing logs and latency samples generated by benchmark runs (excluded from Git if large).
- `experiments/processed/`: Computed statistical summaries and aggregated benchmark metrics.
- `experiments/figures/`: Publication-ready plots and charts generated by automated scripts.

---

## 3. Required Metadata

Every benchmark run must record:
1. **Git Commit Hash**: Exact repository state used during execution.
2. **Environment & Hardware**: GPU model(s), VRAM, CUDA version, driver version, CPU/RAM.
3. **Model & Runtime**: Model identifier, quantization settings, vLLM / engine arguments.
4. **Workload Specification**: Arrival distribution (e.g. Poisson, constant), prompt length, output length, concurrency level.
5. **Routing Policy**: Routing algorithm name and configuration parameters.
6. **Random Seed**: Seed used for stochastic processes (arrival times, token sampling).
